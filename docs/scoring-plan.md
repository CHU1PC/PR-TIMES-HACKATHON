# 採点とアドバイスの設計メモ

2026-08-14 時点の合意。**まだ実装していない。**着手前に認識を揃えるための文書。

---

## 1. なぜ分析しているか

### きっかけ

`HomePage.tsx` のランキングが「おすすめ順」と名乗りながら日付順だった。
`filter` はあるが `sort` が1行も無い。

```tsx
const monthlyRankedEvents = useMemo(() => {
  return events.filter((event) => event.date.startsWith(monthPrefix));  // sort が無い
}, [...]);
```

並び替えの基準を決めるため既存の `reach_score` を使おうとしたところ、
**その指標が製品の主張を測れていない**ことが分かった。

### 判明したこと

要件定義 §5.2 の中核仮説 U1 は「地域情報があると届き方が変わる(勝率95.4%)」。
ところが指標ごとに再現性が違う。

| 指標 | 地域あり/なし | ゼロ率 | 企業規模との相関 | 測っているもの |
|---|---|---|---|---|
| `reach` | **0.98倍(再現しない)** | 0.0% | +0.074 | 自動転載されやすさ |
| `regional_reach` | **1.55倍** | 12.7% | +0.054 | 地元に届いたか |
| `page_view` | 1.32倍 → **時期を揃えると 1.05倍(消える)** | 0.0% | -0.007 | 実際に読まれたか |
| `unique_user` | 1.36倍 | 0.1% | -0.006 | 同上(PV と相関0.99) |
| `like_count` | — | 11.2% | — | U4 で不採用済み |

**現行の `reach_score` 加点は、製品が「実測で裏付けた」と言う効果を測れていない。**

**U1 を支えるのは `regional_reach` だけ**である(2026-08-14 追記。次項)。

### PV の 1.32倍 は時期の交絡だった(2026-08-14)

`page_view` には投稿時期による巨大なトレンドがある。同一企業セル内で
「直近3ヶ月 vs それ以前」を比べると **3,982セル・勝率96.6%・中央値比 7.93倍**。
生の年別中央値は 2024年13 → 2026年7月560 で **43倍**。
同じセルで `reach` も `regional_reach` も 1.00倍でまったく動かない。

**PV は累積値ではなく直近の測定窓の値**と見るのが自然(古い記事ほど低い = 蓄積の逆向き)。

地域情報の記載率は 2023年85.0% → 2026年90.4% と上がっている。
つまり「新しい記事ほど PV が高く、新しい記事ほど地域を書く」だけだった。

| セルの切り方 | 地域あり/なし (PV) | 地域あり/なし (`regional_reach`) |
|---|---|---|
| 企業のみ | 1.16倍 (55.6%) | — |
| **企業 × 四半期** | **1.05倍 (51.7%)** | **1.50倍 (74.9%)** |
| 企業 × 月 | 1.05倍 (51.6%) | 1.50倍 (76.7%) |

**PV を使う比較はすべて公開月で正規化する。**生値で語彙を採点するとトレンドを吸う。

### 当初の想定が外れた点

- 「`reach` は企業規模と交絡する」→ **否定**。相関 +0.074 でほぼ無相関だった
- 「PV は `like_count` と同じくゼロ密集だろう」→ **否定**。ゼロ率 0.0%、中央値21
- 「PV は U1 を再現する」→ **否定**。時期を揃えると消える(上記)
- 地域メディアを推す理由は「交絡回避」ではなく「**U1 を再現できる**」だった。これは維持

### ノイズ事例の問題

`reach` 上位は「新年のご挨拶」「年頭所感」で埋まる。内容が空虚なほど全媒体が機械転載するため。

| 指標 | 「新年のご挨拶」の平均順位(0%が最上位) |
|---|---|
| `reach` | 上位 26.7% |
| `regional_reach` | 上位 27.1% |
| **`page_view`** | **下位 64.0%** |

**PV だけがこれを解決する。**読まれていないから。
PV 上位は「室外機の節電」「クレーンゲーム店オープン」など顧客が真似できる事例。

## 2. 最終目標

**LLM が実測に基づいてアドバイスできるようにする。**

```
分析で「◯◯は勝率68%・中央値1.48倍」と実測
  → LLM のプロンプトに根拠として渡す
  → 顧客の予定に対し「こうするともっと届く」と提案
```

数字そのものは顧客に見せない。**傾向として言葉にする。**

## 3. 個別の目標

### 3.1 ランキングの並び順を実測に基づくものにする

`HomePage` の「おすすめ順」を本物にする。日付順をやめる。

### 3.2 壁打ちの質問順と文言を実測で決め直す

現在6問あるが、**裏付けがあるのは2問だけ。**

| 問 | 文言 | 裏付け |
|---|---|---|
| `place` | 地域の経済新聞と地方紙が拾います | **U1: 勝率95.4%・+17.5媒体** |
| `video` | 無ければ撮らなくて構いません | **勝率49.1% = 差が無いと実測** |
| `partner` | 相手側の関係者にも届きます | 未検証 |
| `people` | 何が起きたのかが伝わります | **検証不能**(`main_image_face` 列が存在しない。U5) |
| `novelty` | 「初」が言い切れると… | 未検証 → **今日 62.2%・1.27倍が出た** |
| `observation` | 発表文が具体的になります | 未検証 |

`requirements.md` §6.1 にも「それ以外の順序は未測定」と書いてある。
§6.1 の `tone` 自動降格規約により、裏付けの無いものは `functional` 止まり。

### 3.3 壁打ち後のアドバイスを機能させる

**ここが最大の欠落。**

`/api/proposal` は存在し、提案3件 + 事例8件 + 媒体6件を返す。
しかし**プロンプトが `skipped` を見ていない。**

```
プロンプト冒頭: 「相手がこれからやることは決まっています」
```

「決まっている前提」で書かれているため、顧客が「決まっていません」と答えて
`skipped` に入っても、LLM はそれを言及対象と認識しない。

| 顧客の状態 | 今の出力 |
|---|---|
| 場所が未定 | 場所に触れない。**最大のレバーを黙って捨てている** |
| 全部未定 | 薄い draft のまま検索 → 的外れな提案 |

**壁打ちで6問聞いた意味が半分失われている。**

対象ユーザーを見ればこれは致命的。

| ペルソナ | 状態 |
|---|---|
| ①菓子＋福祉 | 下書き500個あるが未発信。**ネタ不足ではなく絞り込み不能** |
| ②土木コンサル | 事業部新設。催しを伴わない変化 |
| ③きずなノート | 人数が少なくイベントをやる時間がない |

**「決まっていない」が標準状態**なのに、決まっている前提で作られている。

## 4. 決めたこと

| # | 決定 |
|---|---|
| 1 | **数値は顧客に見せない。**「PV が上がりやすい傾向があります」程度の言い方は可 |
| 2 | アドバイスは**壁打ちの最後にまとめて**返す(毎往復ではない) |
| 3 | 「決まっていない」項目には**具体例を提示する**(事例から引く) |
| 4 | **PV 重視か地元重視かを明示的に質問する**(推定しない) |
| 5 | **`page_view` と `regional_reach` を corpus に入れる。**migration + 投入し直し |
| 6 | **採点は「高評価の事例との近さ」**。既存の `search` を流用する |
| 7 | 未定の項目は**「埋めるとどう変わるか」を提示する**(3の具体化) |
| 8 | **地域メディアが薄い県の顧客は PV 側に寄せる**(§6.4 の奈良問題) |
| 9 | **ランキングは `page_view` だけで並べる**(2026-08-14 実装時に判明。下記) |
| 10 | **PV 重視でいく。**決定4 の「PV か地元か」は顧客に聞かない |

### 9 について — ランキングから地域を外した

実装して成分を分けたところ、`regional_score` は予定の種類にほぼ反応しなかった。

| 予定 | PV | 地域 |
|---|---|---|
| 熊本市中央区に新店舗をオープンします | **0.800** | 0.374 |
| 創業50周年を迎えます | 0.641 | 0.492 |
| 新年のご挨拶 | 0.463 | 0.467 |
| 定例の社内会議 | 0.424 | 0.492 |
| 地元の高校生と共同開発したお菓子の販売会 | 0.368 | 0.566 |
| 年頭所感を発表します | 0.346 | 0.500 |

PV は 0.35〜0.80 に開くが、地域は 0.37〜0.57 に張り付く。しかも**オープンが最低**になる。
混ぜると「定例の社内会議」が「新店舗オープン」を上回った。

理由は比べている方向が違うこと。

| | 問い | 使う指標 |
|---|---|---|
| **ランキング** | 予定 A と予定 B のどちらが良いか(**予定どうし**) | `page_view` |
| **助言** | 同じ予定に地名を足すと変わるか(**同じ予定の中**) | `regional_reach` |

U1 は「同じ予定に地域情報を足すと届き方が変わる」という**予定の中**の比較。
ランキングは予定**どうし**の比較なので、別の問いだった。
`regional_reach` と県ごとの重みは助言側に残す。

### 4 について

同じ予定でも狙いで提案が逆になる。

| 狙い | 上がるもの | 提案の例 |
|---|---|---|
| PV 重視 | 全国の読者数 | 「オープン」「誕生」など存在告知の語 |
| 地域重視 | 地元紙の掲載 | 市区町村名を入れる |

ペルソナ①のゴールは売上なので地元寄りのはずだが、**推定せず聞く**と決めた。

2つの狙いが別物であることは実測で裏付いた。PV を動かす語と `regional_reach` を
動かす語の相関は **0.023(n=424語)** で無関係。両方の勝率が60%を超える語は **0語**。

### 6 について

未実施の予定には `reach` も PV も存在しない。測定値を並べ替えることはできないので、
**予定を embedding して高評価の事例に近いほど上に出す。**
`SEARCH_SQL` の `REACH_BONUS` を差し替える形になる。

### 7 について

`slots.py` の `EFFECTS` は既に「埋まると何が起きるか」を文言で持っている。
足りないのは**その予定に即した具体例**なので、事例から引いて添える。

### 5 のコスト(2026-08-14 実測)

**「ETL 再実行」は要らなかった。**重い工程はどちらも済んでいる。

| 工程 | 要否 | 実測 |
|---|---|---|
| 主催者 RDS からの抽出 | **不要** | `data/raw/release_stat.csv.gz` に `page_view` が既にある。corpus 12.9万件を100%カバー |
| 埋め込み(OpenAI) | **不要** | `corpus_vec.npy` 132MB が既にある。行順で対応するので行集合を変えなければ再利用できる |
| `regional_reach` の算出 | 要 | **0.2秒**(`corpus_media.parquet` + `corpus.parquet` の DuckDB 結合) |
| `page_view` の結合 | 要 | **0.0秒**(同上) |
| alembic migration | 要 | 秒 |
| PostgreSQL へ投入し直し | 要 | **34秒**(corpus 129,045行 + `corpus_media` 5,390,479行, ベクトル込み全件) |

**合計1分未満。**並行作業を組む意味がないので、素直に順に進める。

`requirements.md` §5.1 より。

| # | 制約 | この設計への影響 |
|---|---|---|
| 1 | スコアの数値を顧客に見せない | 内部スコアとしてのみ使う |

**書式は効かないので提案する必要がない。**残る語の発見はすべて

## 6. 分析でこれまでに分かったこと

### 6.1 地域メディアの識別

媒体名の文字列ではなく**振る舞い**で判定する。

```
lift = (その県での出現率) / (全国での出現率)
```

| 媒体 | lift | 判定 |
|---|---|---|
| 福井経済新聞 | 94.1 | 地域メディア |
| 松本経済新聞 | 50.1 | 地域メディア |
| 信濃毎日新聞デジタル | 23.2 | 地域メディア |
| さんにちEye 山梨日日新聞 | 2.3 | **全国転載**(名前は地方紙だが振る舞いが違う) |
| SEOTOOLS | 約1.0 | 全国転載 |

閾値は **lift >= 5**。U1 が名指しした「みんなの経済新聞ネットワークと地方紙」がちょうど入る。

既存の `data/regional_media.parquet` の `share` 列は**使えない。**
全国転載される媒体ほど高くなる指標で、地域性の逆を測っている
(生成は `etl/enrich.py` にある。`load_corpus` の `LOOKUPS` に無いのでアプリからは未使用)。

### 6.2 タイトルの語(暫定)

同一企業 × 同一業種セル内、中央値と勝率で判定。

| 語 | セル数 | 勝率 | 中央値比 | 判定 |
|---|---|---|---|---|
| オープン | 700 | 68.0% | 1.48倍 | 効果あり |
| 初 | 1,035 | 62.2% | 1.27倍 | 効果あり |
| 調査 | 299 | 58.5% | 1.23倍 | 弱い |
| 限定 | 774 | 47.5% | 0.96倍 | **効果なし** |
| 数字を含む | 3,730 | 47.5% | 1.00倍 | **効果なし** |

**平均で見ると誤る。**「限定」は全体平均 2.89倍だったが、セル内中央値では 0.96倍。
外れ値が平均を吊り上げていた。U1 が勝率95.4%で採用されたのと同じ基準を使うこと。

### 6.3 3観点の並列分析(2026-08-14 完了)

語彙・構造・文脈の3観点で18件を検証し、反証役を通ったのは8件。
基準は勝率60%以上 かつ 中央値比1.15倍以上。**PV 側は公開月の中央値で正規化した。**

**残ったもの。**

| 発見 | 指標 | セル | 勝率 | 中央値比 |
|---|---|---|---|---|
| 存在告知クラスタ(誕生/オープン/グランド/リニューアル/開設/店舗/ショップ/拠点) | PV | 1,378 | 72.0% | 1.38倍 |
| 他県の県名をタイトルに入れる(**東京を除く**) | `regional_reach` | 597 | 66.7% | 1.27倍 |

- 存在告知は**実拠点を持つ業種に限る。**EC・通販50.7% / システム開発50.9% /
  学校・大学52.6% では効かない。効くのはレストラン71.1% / 百貨店78.3% / ホテル65.7% など
- **自県の県名は効かない**(1,610セル・29.3%・1.00倍)。東京への言及も効かない(102セル・26.5%)
- **PV を動かす語と `regional_reach` を動かす語は無関係**(相関0.023・n=424語)。
  両方の勝率が60%を超える語は0語

**落ちたもの。**

| 主張 | 却下の理由 |
|---|---|
| 記号・括弧が効く | 同一セル内でまったく動かない |
| タイトル長に最適帯がある | 35字以下が弱く不利なだけ。46字以上は差が消える |
| 集客イベント語が PV を下げる | 反証された |
| IR語が `regional_reach` を殺す | 反証された |
| 地域情報ありは `reach` が高い | **東京タグだけで作られていた。**東京を除くと反転する |
| 金額表記が効く | 57.9%・1.156倍で閾値未満 |

### 6.4 `regional_reach` は県間で公平でない

同一企業 × 同一四半期で「その県タグ vs 他県タグ」を39県ぶん比較した。

| 県 | セル | 勝率 | 中央値比 |
|---|---|---|---|
| 秋田 | 297 | 83.2% | 1.60倍 |
| 福岡 | 675 | 73.3% | 1.75倍 |
| 神奈川 | 998 | 68.8% | 1.33倍 |
| 東京 | 2,486 | 40.2% | 0.93倍 |
| 京都 | 659 | 29.9% | 0.67倍 |
| 山梨 | 209 | 14.8% | 0.40倍 |
| **奈良** | 221 | **4.1%** | 中央値 0 (他県は4) |

**媒体の供給量では説明できない。**東京は地域媒体41サイト・掲載27,212件で勝率40.2%、
秋田は2サイト・1,265件で勝率83.2%。決まっているのは
「**その県の地域メディアが PR TIMES を自動転載しているか**」で、顧客の努力では動かない。

生の `regional_reach` をスコアに使うと、奈良の顧客は何をしても低くなる。
これは制約2「出力は必ず出す方向に働く」に抵触する。

**決定8: 地域メディアが薄い県の顧客は PV 側に寄せる。**
奈良・熊本・山梨のように地元紙が PR TIMES を自動転載していない県では、
地元重視の助言をしても届かない。その県の顧客には存在告知側(§6.3)の助言を返す。
どの県を「薄い」とするかの閾値は未定。

## 7. 未決の論点

| # | 論点 | 状態 |
|---|---|---|
| 1 | `partner` / `observation` の裏付けを取れるか。`people` は検証不能で確定 | 未着手 |
| 2 | 「原稿の書き方の支援」との線引き | **解消**(§5。書式は効かない) |
| 3 | 3指標をどう合成するか | **解消。**ランキングは PV のみ、助言は地域(決定9) |
| 4 | PV重視/地元重視の質問を7問目にするか、入口で聞くか | **解消。**聞かず PV 既定(決定10) |
| 5 | ノイズ事例をコーパスから除くか、加点で沈めるか | **解消。**採点が沈めた(新年のご挨拶0.35 対 オープン0.81) |
| 6 | `regional_reach` の県内正規化をどう実装するか | **実装済み。**県内パーセンタイル + 非ゼロ率の重み |
| 7 | 「初」の1.27倍は時系列補正後も残るか | 未検証。ML の特徴量検討で分かる見込み |

### 論点5 について(解消)

「PV だけがノイズ事例を沈める」は正規化前の数字だったので疑っていたが、
正規化後の採点でも沈んだ。「新年のご挨拶」0.35 に対し「新店舗をオープン」0.81。

### 論点7 について

`novelty` スロットを `functional` から `causal` に上げてよいかがこれで決まる。
存在告知クラスタは補正後も 72.0% を保ったが、「初」単体の補正後は測っていない。
`AI` は補正で 1.40倍 → 1.19倍 に縮んだので、縮む可能性がある。

## 8. 実装しないと決めたこと

- **GPU の使用。** 形態素解析は12.9万件を7.2秒で処理でき、集計は DuckDB で完結する。
  必要になるのはクラスタリングや予測モデルを作る場合のみ
- **認証まわりのテスト。** ハッカソンの期限を優先(別途決定済み)
